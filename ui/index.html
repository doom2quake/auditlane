AuditLane · pre-audit cleanroom for Arbitrum

Reproduce the build, then hand it to the auditor.

A cleanroom that folds an Arbitrum repo into one content-addressed manifest: a pinned toolchain, the captured test counts, and every contract's source hash and Arbitrum Sepolia deployed-bytecode hash checked against the built artifact. If the deployed bytecode does not match the artifact, the package fails closed. The same seven reason codes are recomputed on-chain in BuildRegistry.sol.

How it works

one fold, one on-chain reference

Pure fold (auditlane/manifest.py): the manifest id is a function of evidence, so re-running reproduces it byte-for-byte. On-chain (BuildRegistry.sol): the same seven reason codes in the same order, plus a write-once commitment of the manifest id. Fail closed: a deployed bytecode that does not match the built artifact is code 5, never a green pass.

      On-chain reference

      BuildRegistry.sol · Arbitrum Sepolia

      Simulated in the browser, not a testnet receipt. This page runs the real reproducibility check over the bundled sample repo, so the manifest id, hashes and reason codes are computed here, not read from a screenshot. What comes straight from src/BuildRegistry.sol: the ManifestCommitted(bytes32,address,uint16) event, its topic0 0xf3a3cee0…, and the AlreadyCommitted(bytes32) error selector 0xd297b6c5. There is no transaction hash or block number, because nothing is broadcast here, and none is invented. Verify with cast keccak "ManifestCommitted(bytes32,address,uint16)".

      What am I looking at?
      Reproducible
      Every check cleared: toolchain pinned, build had sources, tests green, each contract's source present, and the deployed bytecode matches the built artifact. The manifest id can be committed on-chain.
      Not reproducible
      A check failed. The reason codes are shown in their fixed order. The agent never emits a green manifest a failing check produced.
      Deployment toggle
      Flip it to simulate a deployed contract whose on-chain bytecode differs from the built artifact. The deployed hash is recomputed, the match flips to MISMATCH, and the verdict becomes NOT REPRODUCIBLE with code 5.
      Manifest id
      A SHA-256 over the canonical payload (toolchain, source hashes, test counts, per-contract hashes and addresses). Pure: the same repo state yields the same id. Tampering with the deployment changes it.
      Agent run trace
      The real build steps: start run, scan, resolve on-chain bytecode, reproducibility check, ActionLimiter guardrail, manifest. A green tick passed, red failed.
